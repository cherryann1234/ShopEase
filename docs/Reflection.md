# Reflection

I used HTMX partials wherever only part of the screen changed: live catalog search and filtering, pagination, add-to-cart, cart quantity updates, the shipping-method total, and inline stock/active changes on the management table. In these cases a full reload would throw away scroll position, half-typed form data, and the sense of speed the store wants, while HTMX let me keep all logic and validation on the server and simply return small HTML fragments. Checking the `HX-Request` header meant the same view could serve a partial to HTMX and a full page to a normal request, so nothing depended on JavaScript. I kept full-page rendering for first loads, navigation, the product create/edit pages, and the order confirmation, because those are new resources with their own URLs that people bookmark or print. After a successful form submit I used `HX-Redirect` so the address bar and messages behave like a normal redirect, while failed submits swap the form in place with errors and preserved input. The trade-off is more partial templates to maintain, but it kept the interface responsive without a JavaScript framework.
